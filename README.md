# LimitDoctor

Отчёт о расходе лимита Claude Code по локальным логам: сколько съел каждый чат, куда ушли токены (обвязка, переписка, холодные старты, ответы), что было бы на другой модели и effort, лента вызовов, где каждый вызов модели — столбик. Центральный дашборд по всем чатам за неделю лимита: сравнение чатов на каждой модели, прогноз к сбросу, во сколько раз окупилась подписка, когда горит лимит (день недели × час), откуда холодные старты. Сверху дашборда — по часам: сколько процентов недели съели мы и сколько остальной аккаунт. Ничего не отправляет наружу.

## Запуск

Нужен только Python 3.8+, без пакетов, один файл. Логи Claude Code находятся сами (`$CLAUDE_CONFIG_DIR`, `~/.config/claude`, `~/.claude`).

```
python src/limitdoctor.py              # отчёт по всем чатам, откроется в браузере
python src/limitdoctor.py --chat       # один чат — тот, из папки которого запущено
python src/limitdoctor.py --chat ID    # один чат по началу id
python src/limitdoctor.py --no-open    # не открывать браузер; --out ПАПКА — куда писать
python src/limitdoctor.py --plan 100   # цена подписки в $ за месяц (по умолчанию 200)
```

Отчёт появляется рядом с файлом `limitdoctor.py` — никаких новых папок (или в `$LIMITDOCTOR_DIR`, если задан).

## Страница с кнопкой и сводка для нейросети

```
python src/limitdoctor.py --serve                                  # страница http://127.0.0.1:8077, кнопка «Снять данные»
python src/limitdoctor.py --brief                                  # то же коротко текстом: последние сутки по часам
python src/limitdoctor.py --snap 41 --h5 16 --reset "25.10 05:00"  # сдать процент Claude (весь аккаунт), потом сводка
```

`--serve` держит крошечный сервер только на этом компьютере (127.0.0.1): открыл страницу — смотришь, нажал «Снять данные» — отчёт собран заново по свежим логам (от десяти секунд до минуты: зависит от того, сколько логов накопилось). Выключить — Ctrl+C или закрыть окно. Правил брандмауэра, автозапуска и служб нет.

Сверху — период. Кнопки **Сутки**, **2 дня**, **Неделя** (последние 7 дней) и **Всё время**. Под ними — полоса дней за всю историю логов: столбик — день, высота — сколько съедено, цвет — модель. Нажми на день — отчёт за этот день; протяни мышкой по полосе — за несколько дней; белые ручки двигают края. Пунктир — сброс недельного лимита Claude, кружок над последним сбросом выбирает неделю лимита. Для привычных есть и поля «от / до» с календарём — они и полоса показывают одно и то же. Период действует на всё: дашборд, список чатов слева и открытый чат (он остаётся открытым при смене периода). Логи читаются один раз при запуске (за всё время — столько же, сколько за месяц), смена периода — пара секунд. В «Расходе по дням» нажми на день — раскроется, сколько в нём было вызовов, токенов и долларов по ценам API и какие чаты его съели. Без страницы то же даёт командная строка: `--days 2`, `--since 2026-11-10 --until 2026-11-12`.

Виджет «По часам»: столбик — час. Снизу сплошным — наши чаты (точно, по логам). Сверху штриховкой — то, чего не видно в наших логах: другие люди и устройства на том же аккаунте, claude.ai в браузере и на телефоне, запуски без сохранения сессии (`claude -p --no-session-persistence`), служебные вызовы, а заодно ошибка оценки размера лимита. Claude отдаёт процент только в момент замера, поэтому прирост между двумя замерами минус наш расход за то же время делится поровну на часы промежутка. Треугольник — сам замер, точная точка. Нет замера — так и написано. Над столбиками — полоса «весь аккаунт / мы / остальные / свободно» на последний замер, под ними — темп последних трёх часов и что будет к сбросу. Кнопки: сутки, 3 дня, неделя (видна и прошлая неделя, сброс — оранжевая черта); «только мы» — без чужого слоя, наши столбики крупнее.

`--brief` — то же текстом, для нейросети, которая следит за лимитом: каждая строка — час, `мы 0.37 | ~1.62` (проценты недели; `~` — среднее между замерами, `?` — замера нет). Процент всего аккаунта приходит тремя путями: ответы get_usage, которые чаты получали по ходу работы, подхватываются из логов сами; `--snap 41` — сдать число вручную (claude.ai → Settings → Usage); `--snap-auto` — спросить Claude Code его командой `/usage`, модель при этом не вызывается и токены не тратятся (годится для расписания Windows). Долгий токен из переменной `CLAUDE_CODE_OAUTH_TOKEN` снимку не передаётся: с ним `/usage` показывает только сводку расходов, без процентов подписки. Если снимок не снялся, причина — в `snap_auto.last.txt` рядом с отчётами. Сам отчёт у Anthropic ничего не спрашивает и ключей не читает.

## Отчёт для нейросети и чужой компьютер

```
python src/limitdoctor.py --all           # за всё время: HTML для человека и .md для нейросети рядом
python src/limitdoctor.py --compact-kit   # положить рядом хук и правило «готовь компакт» (сам ничего не включает)
```

Каждый обычный запуск кладёт рядом с HTML `.md` с тем же именем — коротко для нейросети: итоги, по неделям, «а если бы», утечки, проекты, чаты с первой репликой, практики. Файл `limitdoctor.py` можно отдать другому человеку как есть: инструкция для его Claude — в первых строках («прочитай первые 25 строк и сделай, что там написано»). Похожее на токены и ключи в MD скрыто, но названия чатов, папки и начало первой реплики там есть — перед отправкой стоит глянуть.

## Проценты

Проценты в отчёте — доля лимита, которую съели чаты на этом компьютере. Claude в настройках показывает весь аккаунт: облачные сессии, другие компьютеры, других людей на том же аккаунте. Поэтому у него процент выше, и это нормально: с ним отчёт не сверяется. Размер лимита Claude не сообщает; он оценён один раз и лежит в `PARAMS["cap"]` (план Max, $200).

```
python src/limitdoctor.py --week-reset 2026-10-11T02:00Z   # один раз: когда Claude обнуляет неделю (отчёт — от сброса)
python src/limitdoctor.py --effort-check                   # множители effort по своим логам
```

Чтобы видеть рядом весь аккаунт по Claude, подключи статус-строку терминального Claude Code: в `~/.claude/settings.json` — `"statusLine": {"type": "command", "command": "python /путь/к/src/limitdoctor.py --statusline"}`. Она пишет официальные проценты в `account.jsonl`, а дашборд рисует их рядом с нашими чатами: по часам и двумя линиями за неделю.

## Как устроено

Всё в одном файле `src/limitdoctor.py`: он читает логи, считает цену каждого вызова в хайку-токенах (1 ХТ = цена входного токена Haiku 4.5 = $1 за миллион) и вклеивает данные в шаблон страницы, который лежит в конце того же файла. Цены и множители effort — словарь `PARAMS` в начале файла. Подробное устройство для разработчика и для нейросети — в шапке файла.

**Цены** — по справочнику Claude API на 17.11.2026, у каждой версии модели своя: Opus 4.5–5 дороже Opus 5.5, у Sonnet 5.5 чтение кэша вдвое дешевле, чем у Sonnet 5, Haiku 5.5 на запросах до 100 тыс. токенов в 10 раз дешевле Haiku 4.5, а выше порога — в 2 раза. Чтение и запись кэша у Haiku 5.5 в справке не названы — взяты по обычным долям цены входа, это оценка. «А если бы на другой модели» считает по самой новой версии того семейства.
